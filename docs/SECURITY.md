# 보안과 개인정보

[← README](../README.md)

이 문서는 **v0.15.0-preview.1의 보호 동작과 적용 범위**를 설명합니다. 기능 검사 통과는 독립 보안 감사·침투 테스트·보안 인증을 의미하지 않습니다. 앱의 보안은 Windows·WebView2 Runtime·접속하는 NAS와 인증서 신뢰 환경에도 의존합니다. 검사 범위는 [개발/검증](DEVELOPMENT.md)을 참고하세요.

## HTTPS와 주소 이동 제한

| 보호 항목 | 현재 동작과 범위 |
| --- | --- |
| HTTPS 접속 | 사용자 접속 주소와 QuickConnect 확인 요청에 HTTPS를 사용합니다. 공식 QuickConnect HTTP 입력을 받는 경우에도 요청 전에 HTTPS 주소로 정규화합니다. |
| 인증서 검증 | WebView2와 .NET의 기본 HTTPS 검증을 유지합니다. 인증서 오류 무시·예외 승인·검증 비활성화 기능을 제공하지 않으며, 별도 인증서 고정도 구현하지 않습니다. |
| 직접 NAS 연결 | 앱 내 **최상위 페이지 이동과 새 창**을 설정한 HTTPS 호스트·포트로 제한합니다. 같은 출처 안의 경로는 제한하지 않습니다. |
| QuickConnect 이동 | 설정 ID의 공식 연결 정보와 기기 식별값을 확인한 추가 HTTPS 출처만 현재 연결의 메모리 허용 목록에 넣습니다. `quickconnect` 하위 도메인 전체를 신뢰하지 않습니다. |
| 주소 변경 후 처리 | 이전 연결의 확인 결과·진행 중 검증을 폐기해 늦게 도착한 응답이 새 연결을 덮어쓰지 않도록 합니다. |

직접 HTTP 접속과 주소의 `user:password@host` 형식은 허용하지 않습니다. 신뢰되지 않은 자체 서명 인증서, 만료·이름 불일치 등의 인증서 오류가 있으면 연결하지 못할 수 있습니다. 인증서 신뢰 여부는 Windows·WebView2 등의 기본 검증에 따릅니다. 앱에서 경고를 우회하는 대신 NAS 관리자에게 정상 인증서와 관리 주소를 확인하세요.

**외부 웹 콘텐츠는 기본적으로 차단합니다.** WebView2의 리소스 요청과 프레임 탐색 이벤트에서 현재 NAS의 확인된 출처를 검사합니다. 외부 로그인·패키지가 필요한 경우 **보안 → 이 NAS의 외부 웹 콘텐츠 허용**을 켤 수 있으며, 허용 여부는 NAS 식별 기준별로 저장합니다. 이 옵션은 최상위 주소 이동 제한이나 인증서 검증을 해제하지 않습니다.

QuickConnect가 연결 경로를 찾는 초기 포털 단계에는 외부 HTTPS 콘텐츠를 허용하는 호환성 예외가 있습니다. 이 단계가 NAS의 출처나 권한으로 인정되는 것은 아닙니다. **이 필터는 OS 방화벽이 아니며 WebSocket·WebRTC 등 모든 통신 경로의 완전한 차단을 보장하지 않습니다.** CORS·CSP·혼합 콘텐츠 처리는 기본 웹 엔진 정책을 유지합니다.

구현: [주소 검증](../src/ConnectionAddress.cs) · [탐색 허용 정책](../src/ConnectionSession.cs) · [WebView 이벤트 처리](../src/MainWindow.cs).

## 웹 콘텐츠와 Windows 기능 사이의 경계

- 웹 페이지의 **네이티브 호스트 객체 접근과 WebMessage 통로를 비활성화**합니다. 페이지에 파일 시스템·셸 실행용 앱 브리지를 제공하지 않습니다.
- 설정한 NAS 출처 이외의 웹 권한 요청은 거부합니다. NAS 출처의 권한은 WebView2 기본 동작과 기존 권한 결정을 따르며, 모든 권한을 일괄 거부하거나 항상 새로 묻도록 강제하지는 않습니다.
- 웹 페이지의 외부 앱 URI 스킴 실행을 취소합니다. 사용자 동작으로 열린 미허용 HTTPS **새 창**은 확인 후 운영체제 기본 브라우저로 넘길 수 있습니다. 일반 외부 페이지 이동은 앱 안에서 차단합니다.
- 문서 생성 시 기본 스크롤바를 꾸미는 고정 스크립트를 넣습니다. 이 스크립트는 로그인·폼 데이터 수집이나 네이티브 명령 실행 통로를 제공하지 않습니다.
- 실행 매니페스트는 `asInvoker`이며 관리자 승격을 요청하지 않습니다. 일반 사용자 권한으로 실행하는 것이 WebView2의 [권장 보안 원칙](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)에 맞습니다.

앱은 다운로드 파일에 대한 자체 악성코드 검사나 NAS의 취약점 검사를 제공하지 않습니다. 신뢰하는 NAS 주소와 파일을 사용하고 Windows·NAS·Runtime의 보안 업데이트를 유지하세요.

## QuickConnect 확인과 외부 서비스 통신

QuickConnect 모드에서는 Synology 포털이 선택한 경로를 확인하기 위해 다음 절차를 사용합니다.

1. 입력 ID와 서비스 경로로 공식 QuickConnect 연결 정보를 조회합니다.
2. 응답에 명시된 HTTPS 호스트·포트인지 확인합니다.
3. 후보 NAS의 응답과 연결 정보의 기기 식별값이 일치하는지 확인한 뒤 이동을 허용합니다.

기기 식별값의 MD5 비교는 프로토콜의 일치 확인이며, 비밀키 서명·기기 소유권·로그인 권한을 증명하지 않습니다. 확인은 Synology 서비스·DNS·HTTPS 신뢰 체계에 의존합니다. 확인용 요청에는 브라우저 프로필의 쿠키나 NAS 로그인 자격증명을 가져와 사용하지 않고, 자동 리다이렉트를 끄며 시간·응답 크기를 제한합니다. 구현은 [QuickConnectResolver.cs](../src/QuickConnectResolver.cs)에서 확인할 수 있습니다.

**HTTPS 주소 모드는 내부 호스트명을 QuickConnect ID로 해석해 Synology에 보내지 않습니다.** QuickConnect 모드를 선택하면 ID·서비스 경로가 Synology에 전달되고, 확인 과정에서 반환된 NAS 후보 주소에도 요청할 수 있습니다.

앱 소스에는 별도 사용 분석·텔레메트리 수집 전송 기능을 구현하지 않았습니다. 다만 NAS 웹 페이지가 불러오는 외부 서비스, Synology QuickConnect, WebView2 Runtime의 네트워크 동작까지 없다는 뜻은 아닙니다.

## 로그인과 세션

- 로그인은 NAS가 제공하는 웹 화면에서 처리합니다. 앱이 계정·암호 입력 폼을 별도로 만들거나 로그인 API를 대신 호출하지 않습니다. Chrome·Edge 브라우저의 로그인 상태를 가져오지 않습니다.
- 비밀번호 자동 저장과 일반 폼 자동 완성을 모두 끕니다. 로그인 쿠키·토큰·웹 저장소는 NAS의 세션 처리를 위해 남을 수 있습니다.
- 최소화·앱 종료·모달 닫기·테마 변경·주소 기록 삭제는 NAS의 로그아웃이나 저장된 브라우저 데이터 삭제를 수행하지 않습니다. 로그아웃은 NAS 웹 화면에서 하세요.
- 재실행 후 로그인 유지 여부는 NAS의 로그인 유지 선택·세션 만료 정책과 WebView2 저장 상태에 따릅니다. 항상 로그인 상태가 유지된다고 보장하지 않습니다.
- **NAS 식별 기준마다 이름 있는 WebView2 프로필을 분리합니다.** 직접 HTTPS 주소는 호스트·포트 기준이며 같은 출처의 서로 다른 경로는 같은 프로필을 사용합니다. QuickConnect는 ID·지역 도메인 기준입니다. 동일 기준의 NAS와 그 팝업은 쿠키·웹 저장소·권한을 공유합니다. 다른 Windows 프로세스에 대한 보안 경계를 추가하는 기능은 아닙니다. 구현: [BrowserProfileIdentity.cs](../src/BrowserProfileIdentity.cs).

0.13에서 사용하던 공유 `Default` 프로필은 새 프로필로 복사하거나 자동 삭제하지 않습니다. 업데이트 후 처음에는 다시 로그인해야 할 수 있으며, 이전 프로필의 데이터는 남아 있습니다.

**보안 → 현재 NAS 로그인 데이터 삭제**는 같은 NAS의 팝업을 닫고 빈 화면으로 이동한 뒤 현재 프로필의 `AllProfile` 데이터를 지웁니다. 삭제 후 자동으로 NAS를 열지 않으며 **NAS 홈**으로 다시 연결할 수 있습니다. 다른 NAS의 프로필·주소 기록·기존 공유 Default 프로필은 유지됩니다. NAS 서버 측 세션을 취소하는 기능은 아니므로 서버의 로그아웃·세션 관리도 따로 사용하세요.

## 개인정보와 로컬 데이터

사용자 데이터의 기본 위치는 **`%LOCALAPPDATA%\NasDesk`**입니다. 예전 프로젝트 이름에서 업데이트하더라도 이 경로를 유지합니다.

| 위치 | 저장하는 내용 |
| --- | --- |
| `connection.json` | 현재 접속 주소와 방식, DPAPI로 보호 |
| `address-history.json` | NAS 이름·전체 URL·방식, 최대 30개, DPAPI로 보호 |
| `appearance.json` | 색상 테마와 화면 모드 |
| `security.json` | 프로필 식별 키별 외부 콘텐츠 허용 여부, 평문 JSON |
| `WebView2/` | Runtime이 관리하는 NAS별 쿠키·캐시·웹 저장소·권한과 기존 프로필 데이터 |

**현재 연결과 주소 기록은 Windows DPAPI `CurrentUser`로 보호한 JSON 봉투에 저장합니다.** 기존의 정상적인 평문 파일은 다음 앱 시작 시 보호 형식으로 전환하며, 전환에 실패하면 원본을 유지하고 오류를 표시합니다. 개인 개발용 `connection.local.json` 원본은 자동으로 바꾸지 않습니다.

DPAPI는 저장된 파일의 보호 수단이며, **같은 Windows 사용자 권한으로 실행되는 악성 프로세스를 막지 못합니다.** 다른 계정·PC로 파일을 옮기면 주소를 다시 입력해야 할 수 있습니다. 브라우저 프로필은 WebView2 Runtime이 관리하며 이 JSON 보호와는 별개입니다.

경로·쿼리·프래그먼트를 포함한 전체 URL을 저장할 수 있습니다. 알려진 토큰 매개변수 검사는 자동 최근 기록의 추가 저장을 줄이는 용도이며, 수동으로 추가한 URL의 비밀 값을 모두 탐지·제거하지는 않습니다. 로그인 완료 후의 토큰 URL 대신 NAS의 기본 관리 주소를 저장하세요.

데이터 폴더나 스크린샷을 공유할 때 주소·이름·토큰·쿠키 등 민감한 내용을 확인하세요. 이 앱의 주소 기록은 웹 페이지 전체 방문 이력을 수집하는 기능과는 구분되지만, WebView2 자체 프로필에는 브라우저 데이터가 남을 수 있습니다.

`connection.local.json`, 주소 기록 파일, `.packages/`, `dist/`, `test-output/`은 Git에서 제외합니다. **공개 ZIP은 EXE와 필수 DLL 3개만 선별**하며 사용자 설정·이름·기록·프로필을 포함하지 않습니다. 개인 실행 폴더 전체를 공유하지 마세요.

데이터 초기화 방법은 [사용/초기화](USAGE.md)를 참고하세요. 로컬 프로필을 지우는 것과 NAS 서버에서 세션을 취소하는 것은 다릅니다. 서버 측 세션 종료가 필요하면 NAS의 로그아웃·세션 관리 기능을 사용하세요.

## 배포 파일과 무결성 확인

현재 EXE는 **코드 서명되지 않은 프리뷰**입니다. [v0.15.0-preview.1 릴리스 첨부 파일](https://github.com/JooWon0712/nas-desktop-app/releases/tag/v0.15.0-preview.1)의 ZIP과 `SHA256SUMS.txt`를 함께 내려받아 같은 폴더에 두고, 그 폴더에서 실행하세요.

```powershell
$expectedHash = ((Get-Content -LiteralPath .\SHA256SUMS.txt -Raw).Trim() -split '\s+')[0]
$actualHash = (Get-FileHash -LiteralPath .\NasDesktop-windows-x64.zip -Algorithm SHA256).Hash
$actualHash -eq $expectedHash
```

`True`가 나오면 해시가 일치합니다. SHA-256 일치 확인은 파일 무결성 확인 수단이며 게시자 코드 서명이나 보안 감사를 대신하지 않습니다. 빌드·패키징 방법과 검증 범위는 [개발/검증](DEVELOPMENT.md)을 참고하세요.

현재 CI 구성은 공개 저장소의 기본 브랜치에서 만든 ZIP에 GitHub 빌드 출처 증명을 생성하도록 되어 있습니다. 실제 증명이 생성된 **해당 CI 산출물**만 다음 명령으로 확인할 수 있습니다. 로컬에서 따로 만든 ZIP이나 이전 공개 릴리스에 이 증명이 적용됐다고 보장하지 않습니다. 출처 증명은 Windows Authenticode 코드 서명과도 구분됩니다.

```powershell
gh attestation verify .\NasDesktop-windows-x64.zip -R JooWon0712/nas-desktop-app
```
