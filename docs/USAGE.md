# 설치와 사용 안내

[← README](../README.md)

NAS Desktop은 NAS의 HTTPS 웹 관리 화면을 전용 Windows 창에서 사용하는 비공식 앱입니다. 파일 동기화나 자동 백업 기능은 제공하지 않습니다. 다운로드 링크는 [README](../README.md)에서 확인하세요.

이 안내는 **v0.14.0-preview.1** 기준입니다.

## 실행 환경

| 항목 | 조건 |
| --- | --- |
| 운영체제 | Windows 10/11 x64 |
| .NET | .NET Framework 4.8 이상 |
| 웹 엔진 | Microsoft Edge WebView2 Evergreen Runtime |
| NAS | 접근 가능한 HTTPS 관리 주소와 정상적으로 검증되는 인증서 |
| 실행 권한 | 일반 사용자 권한으로 실행 가능. 앱이 관리자 승격을 요청하지 않음 |

WebView2 Runtime이 없으면 [Microsoft 공식 다운로드 페이지](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download-section)에서 설치하세요. 앱 ZIP에는 Runtime을 포함하지 않습니다. 앱 실행에 .NET SDK나 Visual Studio는 필요하지 않습니다.

현재 실행 파일은 코드 서명되지 않은 프리뷰입니다. 다운로드 파일 확인과 인증서·로그인 데이터에 관한 설명은 [보안/개인정보](SECURITY.md)를 참고하세요.

## 설치와 첫 연결

1. README의 **Windows x64 ZIP**을 내려받아 폴더 전체를 압축 해제합니다. GitHub의 `Code → Download ZIP`은 소스 코드입니다.
2. 압축을 해제한 폴더에서 **`NasDesktop.exe`**를 실행합니다.
3. 처음 실행하면 **주소 기록** 모달이 열립니다. 기존 설정이 있으면 저장된 NAS를 열며, 상단 주소창을 클릭해 모달을 열 수 있습니다.
4. **새 주소 추가**에서 접속 방식·주소와 선택 사항인 NAS 이름을 입력하고 **추가**를 누릅니다. 처음 설정할 때 기본 방식은 **HTTPS 주소**입니다.
5. 목록에서 NAS를 선택한 뒤 **선택 NAS 연결**을 누릅니다.
6. 표시된 NAS 웹 화면에서 직접 로그인합니다. Chrome·Edge 브라우저의 로그인 상태를 가져오지 않습니다.

공개 ZIP에는 다음 네 파일이 들어 있습니다. EXE와 DLL을 같은 폴더에 두세요.

```text
NasDesktop.exe
Microsoft.Web.WebView2.Core.dll
Microsoft.Web.WebView2.WinForms.dll
WebView2Loader.dll
```

### 주소 입력 예시

| 방식 | 입력 예시 | 처리 |
| --- | --- | --- |
| HTTPS 주소 | `https://nas.example.com:443/` | 지정한 HTTPS 관리 화면 열기 |
| HTTPS 주소 | `nas.local:443`, `nas` | 생략한 스킴을 HTTPS로 보완. 내부 호스트명을 Synology에 보내지 않음 |
| HTTPS 주소 | `https://192.0.2.10/`, `https://[2001:db8::10]:443/` | IPv4·IPv6 주소 지원 |
| QuickConnect | `my-nas`, `quickconnect.to/my-nas` | Synology QuickConnect ID의 연결 경로 확인 |
| QuickConnect | `quickconnect.cn/my-nas` | 입력한 QuickConnect 지역 도메인 사용 |

예시는 주소 형식을 설명하기 위한 가상 값입니다. 실제 접속 가능한 주소와 포트로 바꿔 입력하세요. 직접 HTTP 접속과 주소의 `user:password@host` 형식은 허용하지 않습니다.

## 창과 주소창 사용

| 조작 | 동작 |
| --- | --- |
| 주소창·테두리·주소 기록 버튼 클릭 | 주소 기록 모달 열기 |
| `Ctrl+L` | 웹 화면에서도 주소 기록 모달 열기 |
| 주소에 포커스를 둔 상태의 `Enter` / `Alt+↓` | 주소 기록 모달 열기 |
| NAS 홈 / 새로 고침 | 저장된 NAS 홈 / 현재 웹 화면 다시 열기 |
| **기본 창**의 X / `Alt+F4` | 기본 창과 관련 팝업을 트레이로 숨김 |
| **팝업 창**의 X | 해당 팝업 창을 닫음. 기본 창은 계속 실행 |
| 트레이 더블클릭 / NAS 창 열기 | 숨겨진 창 복원 |
| 트레이 → 완전 종료 | 앱과 관련 창 종료 |
| 최소화 버튼 | 작업 표시줄로 최소화 |

상단에는 선택한 NAS의 주소와 접속 방식을 **항상 읽기 전용**으로 표시합니다. URL은 표시·복사용이며 직접 타이핑하거나 붙여넣어 연결을 변경할 수 없습니다. 주소 입력과 연결 선택은 주소 기록 모달에서만 수행합니다. 상단에는 별도의 주소 변경·편집·연결 버튼이 없습니다.

NAS가 연 팝업 창의 주소도 읽기 전용이며, 팝업에서는 주소 기록을 열 수 없습니다. 같은 NAS의 팝업은 별도 앱 창으로 열립니다. 이미 실행 중인 앱을 다시 실행하면 기존 창을 엽니다.

Windows가 트레이 아이콘을 숨기면 알림 영역의 `^`에서 찾으세요. 기본 창의 X는 종료가 아니며, 종료하려면 트레이의 **완전 종료**를 선택합니다. Windows 로그오프·종료를 막지는 않습니다.

## 주소 기록 모달

| 조작 | 동작 |
| --- | --- |
| 새 주소 추가 → 추가 | 이름·주소·방식을 기록에 저장하고 해당 항목을 선택. 접속은 유지 |
| 기존 NAS 이름 → 이름 저장 | 목록에서 선택한 항목의 이름 수정 |
| 선택 NAS 연결 | 선택한 주소를 현재 연결 설정으로 저장하고 바로 접속 |
| 삭제 | 선택한 기록만 삭제. 현재 접속 주소와 로그인 데이터는 유지 |
| 닫기 / `Esc` | 연결을 선택하지 않고 모달 닫기. 현재 접속 유지 |

새 주소는 먼저 **추가**를 눌러 목록에 저장한 뒤 **선택 NAS 연결**을 누르세요. 새 주소 입력만 바꾼 상태에서는 목록의 선택 항목이 연결 대상입니다.

이름은 선택 사항이며 60자 이내로 입력합니다. 이름을 비우면 호스트명으로 표시합니다. 기존 이름 없는 기록도 사용할 수 있습니다. 자동 기록과 재연결은 지정한 이름을 지우지 않습니다.

기록은 주소와 접속 방식 기준으로 중복을 정리하고 최근 순서로 최대 30개를 보관합니다. 기록을 삭제해도 현재 접속과 로그인 상태는 유지하며, 앱을 여는 것만으로 삭제한 기록을 다시 추가하지 않습니다. 현재 활성 NAS 연결은 하나이며 기록에서 다른 NAS로 전환할 수 있습니다.

**닫기 / Esc는 이미 저장한 기록 변경을 되돌리지 않습니다.** 모달에서 **추가·이름 저장·삭제**로 저장한 변경은 유지합니다. 연결 설정 저장에 실패하면 모달과 입력·선택을 유지한 채 오류를 표시하고, 기존 연결을 바꾸지 않습니다.

## 보안과 로그인 데이터

상단 **보안** 또는 트레이의 **보안 및 개인정보**에서 현재 NAS의 설정을 엽니다.

- **이 NAS의 외부 웹 콘텐츠 허용:** 기본값은 꺼짐입니다. 외부 로그인·패키지가 차단될 때 필요한 NAS에서만 켜고 새로 고침하세요. 최상위 주소와 인증서 검증은 유지합니다. QuickConnect 초기 연결 경로 확인에는 호환성 예외가 있습니다.
- **현재 NAS 로그인 데이터 삭제:** 현재 NAS의 팝업을 닫고 쿠키·캐시·웹 저장소·권한 등을 지운 뒤 빈 화면에 머뭅니다. **NAS 홈**을 눌러 다시 연결하고 로그인하세요. 다른 NAS의 프로필과 주소 기록은 유지합니다.

삭제는 NAS 서버에서 세션을 취소하는 기능이 아닙니다. 서버 측 종료가 필요하면 NAS의 로그아웃·세션 관리 기능도 사용하세요.

0.14부터 직접 주소의 호스트·포트 또는 QuickConnect의 ID·지역 도메인 기준으로 로그인 프로필을 분리합니다. 같은 출처의 다른 경로는 같은 프로필을 사용합니다. 예전 공유 `Default` 프로필은 복사·자동 삭제하지 않으므로 첫 연결에 재로그인이 필요할 수 있습니다.

주소와 기록은 Windows 계정의 DPAPI로 보호하며 기존 평문 파일은 다음 앱 시작 시 전환합니다. 같은 Windows 계정의 악성 프로세스까지 방어하지는 않습니다. 자세한 범위는 [보안/개인정보](SECURITY.md)를 참고하세요.

## 테마와 다운로드

**테마** 또는 트레이 메뉴에서 **라이트 모드 / 다크 모드 / 시스템 설정 따르기**를 선택할 수 있습니다. 시스템 모드는 Windows의 앱 색 설정을 따르며, 트레이에 숨겨진 상태에서도 변경을 반영합니다. 라이트·다크를 직접 선택하면 Windows 밝기 변경에 영향을 받지 않습니다.

색상 테마는 차콜 블루·그래파이트 바이올렛·웜 앰버·포레스트 그린·세이지 올리브·네이비 민트의 6가지이며 각각 라이트·다크 조합을 제공합니다. 설정은 다음 실행에도 유지합니다. 앱 테마는 창·상단·메뉴에 적용하고 NAS 웹 화면의 밝기는 NAS에서 설정합니다.

파일 받기는 NAS 웹 화면의 다운로드 기능을 사용하며 기본 다운로드 목록은 **Ctrl+J**로 엽니다. 별도 다운로드 버튼은 없습니다. 브라우저 기본 스크롤바의 두께와 대비를 보완하지만 제조사 자체 스크롤 UI에는 다르게 적용될 수 있습니다.

## 연결 실패와 재시도

연결 실패 시 앱 테마에 맞는 안내 화면에서 **다시 연결 / 주소 선택**을 제공합니다.

- **다시 연결:** 연결을 재시도합니다. 재시도 중에도 안내 화면을 유지하고 성공하면 NAS 웹 화면을 다시 표시합니다.
- **주소 선택:** 주소 기록 모달을 열어 다른 주소를 추가하거나 선택합니다.
- HTTP 401/403/407 등 로그인·권한 응답은 NAS의 안내 화면을 유지합니다.

웹 엔진을 재생성할 때도 같은 프로필을 사용하지만 충돌 직전의 미저장 웹 작업 복구는 보장하지 않습니다. 로그인 유지 여부는 NAS의 세션 정책과 저장 상태에 따릅니다. 자세한 세션 설명은 [보안/개인정보](SECURITY.md)를 참고하세요.

## 지원 범위와 알려진 한계

| 항목 | 현재 범위 |
| --- | --- |
| NAS 제조사 | HTTPS 웹 관리 화면을 여는 범용 방식. Synology·QNAP·ASUSTOR·TrueNAS 장비 전체의 동작을 보증하지 않음 |
| 클라우드 ID | Synology QuickConnect 지원. myQNAPcloud·ASUSTOR EZ-Connect 등은 직접 HTTPS 주소 사용 |
| 동시 연결 | 활성 NAS 연결 하나. 기록에서 다른 NAS로 전환 가능 |
| 별도 포트·외부 SSO | 호스트·포트 이동 제한으로 추가 호환 처리가 필요할 수 있음 |
| HTTP·인증서 예외 | 직접 HTTP 접속과 앱 내 인증서 오류 무시 미지원 |
| 2FA·업로드·패키지 | 실제 제조사별 전체 호환성 검증 미완료 |
| 실행 중 자원 | 트레이에 숨겨도 웹 엔진이 CPU·메모리 등을 사용하며 강제 일시 정지하지 않음 |
| 업데이트 | 앱 자동 업데이트 없음. WebView2 Evergreen Runtime의 업데이트와는 별개 |

QNAP·ASUSTOR·TrueNAS 관련 검사는 제조사별 경로·포트를 흉내 낸 **합성 화면** 기준입니다. 한 Synology NAS에서는 읽기 전용 확인으로 QuickConnect 자동 전환과 DSM 로그인 화면 표시를 확인했으며 로그인은 수행하지 않았습니다. 실제 장비의 로그인·2FA·업로드·다중 파일 전송·모든 패키지와 모든 QuickConnect 지역/릴레이 조합을 검증한 것은 아닙니다.

NAS가 오프라인이거나 접근 가능한 HTTPS 경로가 없으면 접속할 수 없습니다. PC 절전·네트워크 단절·NAS 세션 만료도 화면 기능에 영향을 줄 수 있습니다. 앱을 켜 두는 것만으로 PC 파일을 자동 백업하지 않으며 NAS의 서버 작업은 NAS에서 처리합니다.

## 자주 겪는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| DLL을 찾을 수 없음 | EXE만 꺼내지 않았는지, ZIP 네 파일을 함께 압축 해제했는지 확인 |
| WebView2를 준비하지 못함 | 공식 Evergreen Runtime 설치 상태와 사용자 데이터 폴더 쓰기 권한 확인 |
| 연결 거부·시간 초과 | NAS 전원·HTTPS 관리 포트·주소·PC 네트워크·필요한 VPN 확인 |
| 인증서 오류 | 주소와 인증서 이름·유효기간·신뢰 설정을 NAS 관리자와 확인 |
| 다른 주소로 이동이 차단됨 | 최종 HTTPS 관리 주소를 입력했는지 확인. 별도 포트 패키지·외부 인증은 호환성 확인 필요 |
| 외부 로그인·패키지 일부가 표시되지 않음 | 보안 설정의 외부 콘텐츠 차단 여부 확인. 필요한 NAS에서만 허용 후 새로 고침 |
| 주소창에 입력되지 않음 | 정상 동작. 주소창 클릭 또는 Ctrl+L로 모달을 열어 주소 추가·연결 |
| 기본 창의 X를 눌러도 계속 실행됨 | 정상 동작. 트레이에서 완전 종료 선택 |
| Windows 트레이 설정에 NAS Desktop이 여러 번 표시됨 | 이전 실행 경로·테스트의 기록이 남아 있을 수 있습니다. 실행 중인 앱 수와는 다릅니다. 재부팅만으로 사라진다고 보장하지 않으며, 다른 앱의 설정을 보존하면서 해당 기록을 따로 확인해야 합니다. |
| 재실행 후 로그인이 풀림 | NAS 세션 정책·로그인 유지 설정·프로필 저장 상태 확인 |

## 업데이트·제거·초기화

### 업데이트

1. 트레이에서 **완전 종료**를 선택합니다. 기본 창의 X는 종료가 아닙니다.
2. 새 릴리스 ZIP의 EXE와 DLL 3개를 **기존 실행 폴더에 덮어쓰고** 실행합니다. 기존 `NasDesktop.exe`의 전체 경로와 파일 이름을 유지하세요. Windows는 실행 경로가 달라진 앱의 트레이 기록을 별도로 보관할 수 있습니다.
3. 주소·이름·테마는 `%LOCALAPPDATA%\NasDesk`에서 이어 사용합니다. 0.14부터 NAS별 프로필을 사용하므로 이전 공유 프로필의 로그인은 옮기지 않습니다. 첫 연결에는 다시 로그인해야 할 수 있습니다.

이전 **Synology NAS Desktop**에서 이름이 바뀌어도 같은 사용자 데이터 경로를 유지합니다. 앱의 자동 업데이트 기능은 없으므로 새 버전은 README의 릴리스 링크에서 확인하세요.

이전 실행 경로의 기록은 업데이트만으로 자동 삭제되지 않습니다. Windows 설정의 중복 목록이 실제 실행 중인 앱 수를 뜻하지는 않습니다.

### 제거와 데이터 초기화

트레이에서 완전 종료한 뒤 압축 해제한 실행 폴더를 제거하면 됩니다. 시작 프로그램이나 Windows 서비스를 자동 등록하지 않습니다. 실행 폴더를 지워도 사용자 데이터는 남습니다.

초기화가 필요하면 완전 종료 후 파일 탐색기에서 `%LOCALAPPDATA%\NasDesk`를 열어 필요한 항목을 백업하고 삭제하거나 이름을 바꿉니다.

| 초기화할 항목 | 파일 또는 폴더 |
| --- | --- |
| 주소 기록 | `address-history.json` |
| 현재 연결 선택 | `connection.json` |
| 색상·화면 모드 | `appearance.json` |
| NAS별 외부 콘텐츠 허용 설정 | `security.json` |
| 모든 NAS와 이전 공유 프로필의 로그인·사이트 데이터 | `WebView2` 폴더. 저장된 로그인 상태·캐시·권한 등도 함께 초기화 |

현재 NAS의 데이터만 지우려면 파일을 직접 지우는 대신 앱의 **보안 → 현재 NAS 로그인 데이터 삭제**를 사용하세요. 보호된 설정·기록을 다른 Windows 계정이나 PC로 옮기면 주소를 다시 입력해야 할 수 있습니다.

로컬 프로필을 지우는 것과 NAS 서버에서 세션을 취소하는 것은 다릅니다. 서버 측 세션 종료가 필요하면 NAS의 로그아웃·세션 관리 기능을 사용하세요. 데이터별 저장 내용과 주의점은 [보안/개인정보](SECURITY.md)를 참고하세요.

개인 개발 빌드의 실행 폴더에 `connection.local.json`이 있으면 `connection.json`을 지워도 그 주소를 초기값으로 사용할 수 있습니다. 공개 ZIP에는 이 파일이 없습니다.
